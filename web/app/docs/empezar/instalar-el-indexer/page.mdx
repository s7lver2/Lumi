El Indexer es una aplicación de un solo operador: sin cuentas, sin servidor propio, sin nada que
emparejar. Todo lo que necesita para funcionar lo levanta él mismo, la primera vez que se abre.

## Descargar e instalar

Se distribuye por el mismo instalador compartido que el cliente (`installer.exe`, solo Windows por
ahora) — al abrirlo, elige **Indexer** en vez de (o además de) Cliente. Nada le impide convivir en
la misma máquina que un cliente ya instalado; son productos independientes bajo el mismo instalador.

## Instalar WSL2 (requisito en Windows)

El botón "Levantar en WSL" del siguiente paso no instala WSL por ti — solo lo usa una vez ya está
ahí. Si nunca lo has instalado, hazlo antes de abrir el Indexer:

<Codigo titulo="PowerShell, como Administrador" codigo={`wsl --install`} />

Eso activa las características de Windows que hacen falta (Plataforma de máquina virtual,
Subsistema de Windows para Linux), instala WSL2 y, por defecto, una distribución Ubuntu — y pide
**reiniciar** al terminar. Tras el reinicio, Ubuntu se abre solo una vez para que crees tu usuario y
contraseña de Linux (no tienen por qué coincidir con los de Windows).

Para comprobar que quedó bien instalado:

<Codigo titulo="PowerShell" codigo={`wsl -l -v`} />

Debería listar al menos una distribución con `VERSION` en `2` y `STATE` en `Running` o `Stopped` —
nunca vacío.

<Detalle titulo="Problemas más comunes al instalar o usar WSL">
  **"WSL 2 requiere que se actualice el componente del kernel"** — `wsl --install` no siempre trae
  el kernel más reciente. Solución: `wsl --update` y reiniciar otra vez.

  **`wsl --install` no hace nada, o falla en silencio** — casi siempre es la virtualización
  desactivada en la BIOS/UEFI (`Intel VT-x` o `AMD-V`). Actívala ahí, o comprueba desde el
  Administrador de tareas → Rendimiento → CPU si dice "Virtualización: Habilitada". Si las
  características de Windows no se activaron solas, se pueden forzar a mano:

  <Codigo titulo="PowerShell, como Administrador" codigo={`dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart`} />

  **El botón "Levantar en WSL" instala/arranca en la distribución equivocada** — el Indexer llama
  al comando `wsl` sin especificar cuál distribución (`wsl -e sh -lc "..."`), así que siempre usa
  la que esté marcada como predeterminada. Si tienes varias (por ejemplo Ubuntu y una de Docker
  Desktop) y no es Ubuntu la que responde, fija cuál lo es:

  <Codigo titulo="PowerShell" codigo={`wsl --set-default Ubuntu`} />

  **Antivirus o Hyper-V de terceros (VirtualBox, VMware) en conflicto** — WSL2 necesita Hyper-V
  activo; algunos hipervisores de terceros exigen su propio "modo de compatibilidad con Hyper-V"
  para poder convivir. Revisa la documentación de esa herramienta si `wsl --install` completa pero
  las máquinas virtuales dejan de arrancar después.
</Detalle>

## El asistente de la primera vez

El Indexer nace con cuatro pasos, y el primero (la carpeta de datos) ya llega hecho — la crea el
propio proceso al arrancar, así que el asistente abre directo en **Servicios**.

### 1. Servicios: Redis y Qdrant

Redis (la cola) y Qdrant (los vectores) tienen que estar escuchando en `127.0.0.1` antes de poder
hacer nada. En **Linux**, el propio Indexer los arranca nativos sin preguntar. En **Windows** es
distinto, y la app lo dice sin rodeos: Redis no publica binarios oficiales para ese sistema.

<Detalle titulo="Por qué en Windows hace falta WSL">
  No es una limitación de este proyecto en concreto: Redis, sencillamente, no compila un binario
  oficial para Windows. La solución no es empaquetar una alternativa de terceros con su propia
  licencia — es correr los dos servicios dentro de WSL, cuyo reenvío de `localhost` los hace
  alcanzables desde el lado Windows sin exponerlos a la red exterior.
</Detalle>

Si estás en Windows, este paso trae un botón **"Levantar en WSL"**. Requiere tener **WSL2 ya
instalado y habilitado** de antemano (ver arriba) — el Indexer no instala WSL por ti, solo usa el
comando `wsl` para hablar con la distribución que ya tengas. Al pulsarlo:

1. Si Redis o Qdrant no están instalados dentro de tu distribución, los instala ahí — Redis desde
   los repositorios de la distro, Qdrant como binario oficial fijado a `~/.lumi-indexer/bin`, sin
   tocar nada fuera de tu carpeta de usuario.
2. Los arranca como procesos **hijos** del propio Indexer, ligados solo a `127.0.0.1` — si cierras
   el Indexer, mueren con él, no quedan sueltos ocupando el puerto.

<Codigo titulo="lo que corre dentro de WSL, para quien quiera verlo" codigo={`redis-server --bind 127.0.0.1 --protected-mode yes --port 6379 --dir "$HOME/.lumi-indexer"
qdrant  # con QDRANT__STORAGE__STORAGE_PATH en "$HOME/.lumi-indexer/qdrant"`} />

La primera vez esto baja paquetes reales — puede tardar unos minutos. El paso se puede cerrar y
retomar: al reabrir el Indexer, primero intenta **adoptar** cualquier servicio que ya esté vivo
(de una ejecución anterior o de WSL) antes de plantearse lanzar uno nuevo.

### 2. Runtime: el entorno de Python

Un `venv` propio con `torch`, para el motor de embeddings — completamente automático, sin ningún
botón que pulsar. Son varios gigabytes, así que puede tardar; igual que el paso anterior, se puede
cerrar la ventana y se retoma solo al volver.

### 3. Identidad (opcional)

Buscar, descargar e indexar funcionan enteros sin ninguna cuenta. Esta pantalla es solo para quien
vaya a **publicar** un índice y necesite que otros sepan quién lo firmó: conecta una cuenta de
GitHub por el flujo de dispositivo (un código de 6 dígitos que se escribe en github.com/login/device),
y al terminar genera una clave de firma propia con su frase de respaldo de 12 palabras — que no se
puede recuperar si se pierde, así que el asistente no deja avanzar hasta marcar "las he guardado".
Se puede saltar del todo y conectar la cuenta más adelante desde Ajustes.

## Después del asistente: claves de los orígenes de red

Buscar territorio funciona de inmediato contra los orígenes que no piden clave (KartaView, Commons,
Monumentos, Wikipedia, Panoramax, WMS ortofoto, iNaturalist, Geograph, OpenAerialMap). Cuatro
orígenes sí necesitan una clave propia pegada en **Ajustes → Orígenes** antes de aparecer en la capa
de disponibilidad — Mapillary, Google, Mapbox Satellite y Flickr —, y ninguno bloquea el arranque:
simplemente no se ofrecen hasta que se añade su clave.
